# SmartGallery 增量汉化流程

> 目标：上游每次发版，只翻译「这次新增或改动的那几句」，不再全量重做，也不再被合并冲突卡住。

## 一、为什么现在可以做到“增量”

这个仓库的汉化体系是**字典式 i18n**：

- `i18n.py` 从 `translations/zh.json` 读译文，键是**英文原文**
- 模板里用 `{{ _('英文原文') }}` 取译文，取不到就回退显示英文原文
- `window.i18n = {{ t | tojson }}` 会把整本字典注入前端

所以汉化成果有两个载体：

| 载体 | 上游会不会改 | 冲突风险 |
| --- | --- | --- |
| `translations/zh.json`（译文数据） | 上游根本没有这个文件 | **零冲突** |
| `templates/*.html` 里的 `{{ _('...') }}` 包裹 | 上游会改模板 | 只在上游动了同一行时冲突 |

结论：**字典只追加、模板只包裹**，增量成本 = 上游新增的那几句英文。

## 二、每次更新的固定动作

### 一条命令（推荐）

```powershell
cd E:\AI\smart-comfyui-gallery\zh-tools
.\sync-upstream.ps1
```

它会依次做：拉取 → 显示上游新提交和改动范围 → 合并 → 冲突则列出文件并给出处理原则 → 合并成功后自动跑体检。

参数：

| 参数 | 作用 |
| --- | --- |
| `-NoScan` | 只合并，不体检 |
| `-Abort` | 放弃本次合并，回到合并前 |

### 手工分步（等同上面的脚本）

```powershell
cd E:\AI\smart-comfyui-gallery

git fetch origin --prune
git log --oneline HEAD..origin/main          # 上游新提交
git diff --stat HEAD...origin/main           # 改了哪些文件

git merge origin/main                        # 有冲突就按下面第五节处理

python zh-tools\zh_scan.py                   # 体检：还有哪些没汉化
```

## 三、体检结果怎么处理（三种情形）

`zh_scan.py` 会分四类报出来，每类对应一个动作：

### 情形 1：未包裹 —— 上游新加了英文界面元素

```
[index.html]
  未包裹 3 处：
    L1700  文本  Continue browsing
    L1712  属性  Search your library
```

动作：

```powershell
python zh-tools\zh_scan.py --apply      # 自动包成 {{ _('原文') }}
git diff -- templates/                  # 必须复核，确认没包错地方
```

自动包裹只处理**单行、纯文本的 HTML 文本节点和常用属性**（`placeholder / title / aria-label / alt / data-tooltip / data-title`），`<script>`、`<style>`、`<!-- -->`、`<pre>`、`<textarea>` 里的内容一律跳过，所以不会误伤 JS 和 CSS。

包完它会自动把新键补进 `en.json`（en 是恒等映射，只用于登记全量键）。

### 情形 2：缺中文译文 —— 包了 `_()` 但 zh.json 里没有这个键

```powershell
python zh-tools\zh_scan.py --emit       # 生成 zh-tools\reports\待翻译.json（值都是空串）
# 打开 reports\待翻译.json，把空串填成中文
python zh-tools\zh_scan.py --merge zh-tools\reports\待翻译.json
```

`--merge` 只追加键、自动给上一行补逗号、保持 CRLF 和 2 空格缩进，并当场校验 JSON 合法性；空值会被跳过，不会把空字符串写进字典。

### 情形 3：跨行文本块 / 含插值的文案 —— 工具不碰，人工判断

```
[index.html]
  跨行文本块 3 处（需人工处理）：
    L8     SmartGallery: {{ current_folder_info.display_name }}
    L920   (of {{ total_folder_files }})
```

这类要么是「品牌名 + 动态值」（保持英文即可），要么需要拆句改写。决定不汉化的，直接写进 `zh-tools\ignore.txt`，以后就不会再报。

### 情形 4：上游改了英文文案 —— 旧译文失效

表现是体检报「未包裹」新句子 + 旧键变成「疑似无用键」。动作：

1. `--apply` 包住新句子
2. `--merge` 补上新译文
3. 旧键留着不影响显示，确认没用可删（`--stale` 生成的 `reports\疑似无用键-*.txt`）

```powershell
python zh-tools\zh_scan.py --stale      # 附带列出全仓库都找不到引用的键
```

> 「疑似无用」是**启发式判断**：键可能在 JS 里由变量拼出来、或在 Python 里以转义形式出现，删之前搜一下再决定。

## 四、提交与备份

```powershell
cd E:\AI\smart-comfyui-gallery
git add templates translations zh-tools
git commit -m "汉化: 跟随上游 v2.24.4 增量更新"
```

**重要**：`origin` 指向的是别人的仓库（`biagiomaf/smart-comfyui-gallery`），你的汉化提交推不上去，也**不要**推。汉化成果目前只存在这台机器上。建议：

```powershell
# 先在自己账号下 fork 一份，然后把汉化推到自己的 fork
git remote add mine https://<你的 fork 地址>
git push mine main
```

## 五、冲突处理原则（模板类）

上游和你动到同一行时才会冲突，这时**不要用「使用我的版本 / 使用传入版本」一键搞定**，两边都要：

1. **上游新增的标签、属性、元素** → 一律保留
2. **本地已有的 `{{ _('...') }}` 包裹** → 保留包裹
3. **上游改了同一句英文文案** → 用上游的新英文，同时把 `_()` 里的键换成新英文（旧键留在字典里无害）
4. **上游删了整段功能** → 跟着删，别把废弃代码又救回来

改完：

```powershell
git add <冲突文件>
git commit          # 合并提交
python zh-tools\zh_scan.py
```

不想处理了：`.\zh-tools\sync-upstream.ps1 -Abort`。

### rerere：第二次遇到同样的冲突自动套用旧解法

脚本已给仓库开了本地配置：

```powershell
git config --local rerere.enabled true
git config --local rerere.autoupdate true
```

同一个冲突解决过一次后，下次 Git 会直接按你上次的解法处理并自动 `add`。

## 六、你之前踩过的两个坑，现在怎么避开

### 坑 1：`git stash` + `pull`，报 `templates/index.html: does not exist in index`

原因是上游删/改了那个文件，Sourcetree 的「应用贮藏」默认带 `--index`，找不到原文件就整条失败。
**现在不用 stash**：汉化已经在提交里，直接 `merge origin/main`，Git 用三方合并算差异，不会出现“找不到原文件”。

### 坑 2：用 Python 整文件重写 `zh.json`，一次改了 3743 行

`json.dumps` 会连缩进、分隔符、换行一起改，diff 直接爆炸（还容易被 Git 的 CRLF 转换再搅一遍）。
**现在只用 `--merge`**：纯文本追加一行、补逗号、保持 CRLF，diff 永远只有 1～n 行。

## 七、在 Sourcetree 里对应怎么点

| 流程步骤 | Sourcetree 操作 |
| --- | --- |
| 拉取上游 | 点【拉取】，或用上面的 `sync-upstream.ps1` |
| 解决冲突 | 【文件状态】里右键红色文件 → 打开外部合并工具（推荐 Beyond Compare / VS Code）→ 改完右键【标记为已解决】 |
| 放弃合并 | 菜单【操作】→【中止合并】 |
| 体检 / 包裹 / 合并译文 | 打开仓库根目录的【终端】标签页，跑文档里的命令 |
| 提交 | 勾选改动 → 填说明 → 【提交】 |

## 八、文件清单

| 文件 | 作用 |
| --- | --- |
| `zh-tools\sync-upstream.ps1` | 一条命令：拉取 + 合并 + 体检 |
| `zh-tools\zh_scan.py` | 体检 / 自动包裹 / 生成待翻译清单 / 合并译文 / 查疑似无用键 |
| `zh-tools\ignore.txt` | 故意不汉化的字符串（品牌名、示例语法等） |
| `zh-tools\reports\` | 每次体检的报告、待翻译清单（可随时删） |

### `zh_scan.py` 参数速查

| 命令 | 作用 |
| --- | --- |
| `python zh_scan.py` | 只体检，不改任何文件 |
| `python zh_scan.py --apply` | 自动包裹未包裹的文本/属性，并登记到 en.json |
| `python zh_scan.py --emit` | 生成 `reports\待翻译.json` |
| `python zh_scan.py --merge 文件` | 把填好的译文合并进 zh.json |
| `python zh_scan.py --stale` | 附带列出疑似无用键 |
| `python zh_scan.py --root 目录` | 指定 templates 目录（自测用，不动真实仓库） |

退出码：`0` 全部汉化完毕，`1` 还有待处理项，`2` 找不到 templates 目录。

## 九、日常节奏建议

- 上游发版 → 跑 `sync-upstream.ps1` → 按体检结果补几句 → 提交
- 一次更新通常只有 0～10 句要翻，正常情况下 10 分钟内结束
- 每季度跑一次 `--stale`，清掉历史废弃键，字典不会越滚越肥
